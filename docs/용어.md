# 화면 용어 — 명사형 · 공식 표현

> 화면(메뉴, 버튼, 열 이름, 제목, 안내문, 오류 메시지, 알림)과 서버가 화면에 보내는 메시지에 쓰는 말의 정본이다.
> 새 화면을 만들거나 문구를 수정할 때 이 문서를 따른다. 코드 주석은 해당하지 않는다(주석은 설명이 우선).
> MCP 안내(`mcp_server/guide/GUIDE.md`)와 도구 설명도 개념어는 이 표를 따른다. AI가 사람에게 그 말을 그대로 전하기 때문이다.

## 문체 규칙

2026-11-24 개정. 이전 표의 고유어 조어(판 · 칸 · 선 · 걷어내기 · 다시 켜기 …)는 번역체로 읽혀 업계에서 쓰는 공식 용어로 바꿨다.
바뀐 말은 아래 「바뀐 말」 표에 모았다.

1. **이름은 명사형.** 메뉴, 버튼, 탭, 열 이름, 대화상자 제목, 상태, 배지, 범례, 선택지는 명사로 적는다.
   「~하기 · ~기」로 끝내지 않는다. 예: `전송 데이터 회수`, `재개`, `회수 후 중지`, `즉시 실행`.
2. **짧은 보조 문구는 명사형으로 끝낸다.** 입력란 설명, 빈 목록 제목, 툴팁, 배지 옆 설명, 표 안의 상태 문구가 해당한다.
   예: `SP 0.4.101 이상 지원`, `적용 대기 계획 있음`, `되돌릴 수 없음`, `연결 불가`.
3. **안내 · 결과 · 오류 메시지는 합니다체 문장.** 한 문장에 한 내용만 짧게 적는다. 조치를 요청할 때는 `~하세요`.
   예: `적용 대기 중인 계획이 있어 회수할 수 없습니다. 계획을 적용하거나 다시 실행한 후 진행하세요.`
4. **조어 · 구어를 쓰지 않는다.** 아래 「동작」 · 「바뀐 말」 표의 왼쪽 말이 그것이다.
5. **부정은 `~하지 않습니다` · `~할 수 없습니다`.** `안 ~` · `못 ~` 으로 적지 않는다.
6. **막연한 `~것` 대신 구체적인 명사.** `보낸 것` → `전송 데이터`, `넣은 것` → `적재한 객체`, `바뀐 것` → `변경 사항`,
   `받은 것` → `수신 데이터`.
7. **의인화하지 않는다.** `대상이 말합니다` · `지도가 알립니다` · `홈이 말합니다` → `대상 응답` · `지도에 표시됩니다` ·
   `홈에 표시됩니다`.
8. **문장 부호.**
   - 줄표(—)로 문장을 잇지 않는다. 문장을 나누거나 쉼표 · 괄호를 쓴다. (제목의 `A — B` 형태는 허용)
   - 화면 요소(버튼, 메뉴, 탭, 화면) 이름은 대괄호로 적는다. 예: `[적용]을 클릭하세요`, `SP의 [작업] 화면`.
   - 상태 · 값 · 용어를 인용할 때는 작은따옴표. 예: `상태가 '적용 대기'인 파이프라인`. 낫표(「 」)는 쓰지 않는다.
   - **조사는 앞말에 붙여 쓴다.** 영문 · 숫자 · 괄호 · 따옴표 뒤도 같다. `SP의`, `[적용]을`, `slug는`, `M-0001을`
     (`SP 의`, `「적용」 을` 이 아니다).
   - 문장 안의 나열은 쉼표로 적는다. 가운뎃점(` · `)은 짧은 이름의 짝이나 요약 줄의 구분자에만 쓴다.
   - 괄호 안의 부연은 한 문장에 하나까지. 자세한 설명은 문서로 보낸다.
9. **개념어는 하나로.** 같은 것을 두 이름으로 부르지 않는다(아래 「개념」).
10. **SP 화면의 이름은 SP의 말 그대로.** datarelay가 SP의 화면 · 버튼을 가리킬 때는 SP가 쓰는 이름을 적는다
    (`SP의 [작업] 화면`, `[적용]`, `[잠금 해제]`).

새 기능을 만들 때는 **화면을 짜기 전에** 그 기능의 말을 이 표에 먼저 적는다(AGENTS.md 「화면 용어」).

### 예

| 이전 | 지금 |
| --- | --- |
| 보낸 것을 걷어내고 멈췄습니다 — 계획을 「적용」 해야 들어갑니다. | 전송 데이터 회수 계획을 생성하고 파이프라인을 중지했습니다. 대상에는 계획을 [적용]해야 반영됩니다. |
| 대상 SP(v0.4.100) 는 지우기를 받지 않습니다 — SP 0.4.101 부터. | 삭제는 SP 0.4.101 이상 지원(현재 대상 v0.4.100) |

| 거르기에 걸리는 파이프라인이 없습니다 | 필터 조건에 맞는 파이프라인 없음 |

## 개념 — 중계

| 쓰는 말 | 뜻 | 다른 말로 부르지 않는다 |
| --- | --- | --- |
| 원천 시스템 · 원천 | 데이터를 제공하는 레거시 시스템(PLM, MES)과 중계가 수신하는 API, 파일, 공유 폴더, Kafka 토픽. **원천 시스템의 DB에 직접 접속하지 않는다** | 소스 · 출처 · 레거시(화면에서) |
| 대상 · 대상 인스턴스 | 중계가 적재하는 등록된 SP 인스턴스(자주검증 Datahub, 제조 데이터허브) | 타깃 · 목적지 · 허브(그 인스턴스의 이름이 아니면) |
| 파이프라인 | 원천 하나 → 레시피 → 대상 하나의 단위. slug로 부른다 | 연동 · 잡 · 플로우 · 인터페이스 |
| 정의 · 정의 버전 · 정의 파일 | 파이프라인의 설정(`relay-pipeline/1` — 원천 어댑터, 대상, 실행 주기, 자동 적용). 버전은 DB에 차례로 쌓이는 것, 파일은 서버의 정의 폴더에 둔 것. 같은 slug면 사용 중인 버전이 파일보다 우선한다 | 설정 · 구성 · 판 |
| 레시피 · 레시피 버전 | 원천의 필드를 대상 타입의 속성으로 변환하는 규칙(`sp-table/1`) | 매핑 · 변환 규칙 · 룰 · 판 |
| 필드 · 속성 · 열 | 원천 데이터의 항목(필드) · 대상 타입의 항목(속성, SP의 말) · 어댑터가 만든 표의 열 | 칸 |
| 행 | 원천 데이터의 한 건 · 표의 한 줄 | 줄(데이터의) |
| 관계 | 대상 SP 객체 사이의 연결(SP의 관계 종류) | 선 · 링크 |
| 관계 종류 · 관계 종류 초안 | 관계의 정의(대상 SP의 `relation_types` — 출발 · 도착 타입, 개수 제약, 관계 속성). 레시피의 관계가 쓰는 관계 종류가 대상에 없으면 정의 테스트가 알리고(`relations_missing`) 레시피와 테스트 결과로 초안을 작성한다. 개수 제약은 초안에서 늘 '제약 없음(many_to_many)'이고, 표본의 모양은 참고로만 알린다. 타입 계획으로 대상에 생성한다 | 엣지 타입 · 관계 타입 · 링크 정의 |
| 번들 | 대상 SP에 올리는 표준 데이터 묶음(`sp-bundle/1`). 크기 상한을 넘으면 분할 번들로 나눈다 | 묶음 · 조각 |
| 초안 · 초안(미사용) | 작성했지만 아직 사용하지 않는 버전. 사용 중인 버전이 없는 새 파이프라인은 지도에 '초안(미사용)'으로 표시되고 실행되지 않는다 | 임시 · 드래프트 · 초안(꺼짐) |
| 사용 · 사용 중 · 사용 시작 · 사용 종료 | 버전을 실행에 쓰기 시작하는 것(버튼 [사용])과 그 상태 · 시각, 다른 버전을 사용해 물러난 버전의 상태(다시 사용할 수 있다). **사람이 결정한다** — 화면에서, 또는 대화에서 승인해서(승인 위임). 현재 쓰는 버전은 '현재 정의' · '현재 레시피' | 켜기 · 켜짐 · 내려 둠 · 활성화 · ON |
| 폐기 | 초안을 더 쓰지 않게 하는 것(초안만). 목록에 '폐기'로 남고 본문은 조회할 수 있다 | 버리기 · 삭제(버전의) |
| 작성 경로 | 버전을 작성한 곳 — 화면 · MCP | 지은 곳 · 출처 |
| 초안 작성 · 원본 버전 · 초안 저장 | 사람이 화면에서 레시피 · 정의의 초안을 만드는 것. 원본 버전(사용 중인 버전 · 정의 파일의 레시피 · 이전 버전)을 불러와 수정하고 새 초안으로 저장한다. 원본 버전은 변경되지 않는다. 저장 전에 '원본 대비 변경 사항'을 표시한다 | 출발 판 · 편집 저장 · 복제 |
| 규칙 편집 · JSON 편집 | 초안 작성의 두 보기. 타입별 속성 규칙(열, 다른 타입의 식별자, 고정값, 값 매핑, 날짜 변환, 대문자 변환)을 수정하는 표와 레시피 원문 | 칸 · 본문 |
| 값 매핑 | 속성 규칙의 값 변환 — 원천 값 → 대상 값('01' → '양산') | 대응 · 코드 변환 · 치환 |
| 클라이언트 인증서 · 호스트 키 지문 | 원천이 요구하는 인증서(mTLS, 정의에는 서버 인증서 폴더 안의 파일 이름만) · SFTP 서버를 확인하는 지문(`SHA256:…`) | 클라 인증서 · 핑거프린트 · known_hosts |
| 탐색 · 원천 탐색 | 주소와 인증만으로 원천을 조회해 필드 위치, 예시 값, 열 이름을 확인하는 것. 식별자, 변경 시각, 삭제 표시, 이름 필드의 후보와 목록 위치, 페이지 처리 방식의 추정을 함께 제공한다 | 스캔 · 디스커버리 |
| API 명세 · 명세 분석 | 원천 시스템이 제공하는 API 설명(OpenAPI, Swagger, OData `$metadata`, WSDL, 문서 화면)과, 이를 분석해 서버 주소, 인증 방식, 목록 조회, 필드, 페이지 처리, 증분 조회를 추출하는 것(MCP `source_spec`). 원천 담당자가 작성한 문서이므로 **값으로만** 읽는다 | 지침서 · 스펙 · API 문서 파싱 |
| 페이지 처리 | 원천 API가 목록을 여러 페이지로 나눠 주는 방식 | 쪽 넘김 · 쪽 넘기기 |
| 행 분할 · 열 그룹 | 원천 한 행을 대상의 정의에 따라 여러 타입의 객체와 관계로 나누는 것(일괄 초안 생성의 기본), 이때 한 타입으로 묶은 열들(원천 위치 `task.*` · 열 이름 `TASK_*`). 같은 원천이 관리하는 타입만 생성하고, 다른 원천이 관리하는 기준정보는 참조만 한다 | 나누기 · 열 묶음 · 분해 · 플래튼 |
| 허용 주소 | AI의 탐색 · 테스트가 접속할 수 있는 원천 · 대상 SP 주소 — 서버 설정, 화면에서 추가한 주소(재시작 불필요), 사용 중인 정의의 주소. 대상 SP 주소는 원천 주소로 쓸 수 없다. 변경은 사람이 화면에서, 또는 대화에서 승인해서(승인 위임) | 화이트리스트 · 방화벽 |
| 샘플 데이터 · 테스트 수신 · 테스트 수신함 | 원천에서 수신하지 않고 테스트에 넣는 행(원천이 보내는 형식) · 푸시 원천이 사용 전에 `?trial=1`로 한 번 보내 보는 것 · 그 데이터가 쌓이는 곳(실행은 읽지 않는다) | 견본 행 · 시험 수신 · 테스트 큐 |
| 사이드바 그룹 | 대상 SP 사이드바에서 타입을 모아 보여 주는 단위(SP 정의의 `groups`, 타입의 `nav_group_slug`, SP 화면의 '묶음'). 타입 계획 · 일괄 초안 생성은 같은 원천의 타입이 있는 그룹 › 이름이 같은 그룹 › 새 그룹 순으로 선택한다 | 사이드바 묶음 · 메뉴 그룹 · 카테고리 |
| 타입 계획 | 대상 SP에 없는 타입의 정의를 원천 이름과 함께 대상의 미리 보기 계획으로 생성한 것. 적용은 사람이 대상 SP 화면에서 | 스키마 배포 · 온톨로지 등록 |

| 테스트 · 정의 테스트 · 레시피 테스트 | 대상에 아무것도 전송하지 않고 원천을 수신해 보고, 레시피로 변환해 보고, 기준 출력과 비교하는 것. 결과의 '사용 시 전송 예정'이 사용 후 첫 실행의 전송 건수다 | 시험 · 드라이런 · 미리 실행 |

| 계획 · 계획 생성 | 실행이 대상 SP의 검토함에 **미리 보기**로 등록한 변경 사항. 파이프라인마다 하나만 대기한다 | 플랜 · 변경안 |

| 생성 · 변경 · 삭제(계획의 건수) | 계획이 대상에서 생성 · 수정 · 사용 중지 또는 해제하는 것. **삭제는 객체를 지우지 않고 사용 중지하며, 관계는 해제한다**(회수의 '삭제'는 예외) | 새 · 바뀜 · 무덤 · 선 끊기 |
| 삭제 표시 | 원천이 해당 행의 삭제를 알리는 필드 | 지움 표시 · 삭제 플래그 |

| 자동 적용 | 실행 주기에 따른 실행이 생성한 계획이 기준(사람 적용 3회 이후, 오류 0, 삭제 없음 또는 삭제 포함, 건수 상한)을 충족하면 사람 없이 적용하는 것. 버전마다 정의에 기록하고 사람이 정한다. 기록하지 않으면 '미사용' | 오토 커밋 · 자동 반영 · 자동 승인 |

| 정상 · 적용 대기 · 중단 · 지연 · 실패 · 정의 오류 · 미실행 · 회수 후 중지 | 파이프라인의 상태. 중단은 미해결 · 계획 오류 · 수신 검증으로 전송하지 않은 상태, 지연은 실행 주기상 끝났어야 할 실행이 끝나지 않은 상태(작업 워커 중단, 실행 정체, 실행 주기 타이머 미동작 — `RELAY_LATE_MINUTES`), 실패는 작업이 오류로 끝난 상태(원천 연결 불가 등), 정의 오류는 정의를 읽지 못한 상태, 회수 후 중지는 전송 데이터를 회수한 후 사람의 재개를 기다리는 상태 | 멈춤 · 늦음 · 실행 전 · 걷어내고 멈춤 · 에러 · 블록 |
