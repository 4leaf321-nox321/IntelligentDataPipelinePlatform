# 화면 용어 — 명사형 · 공식 표현

> 화면(메뉴 · 단추 · 열 이름 · 제목 · 안내문 · 오류 메시지 · 알림)에 쓰는 말의 정본. 새 화면을 만들거나 문구를
> 고칠 때 여기 표를 따른다. 코드 주석은 해당 없다(주석은 설명이 우선). 틀(Standard Platform)의 `docs/용어.md` 와
> 규칙 · 동작이 같고, 개념은 이 플랫폼(데이터 중계)의 것이다. MCP 안내(`mcp_server/guide/GUIDE.md`)도 개념어는
> 이 표를 따른다 — AI 가 사람에게 그 말을 그대로 전한다.

## 규칙

1. **이름은 명사형.** 단추 · 메뉴 · 열 이름 · 대화상자 제목 · 상태는 「~하기 · ~기」 가 아니라 명사 — 「사용」 「폐기」
   「보정 계획 생성」 「작성 경로」.
2. **동작은 공식 동사.** 안내문에서 동작을 말할 때는 아래 「동작」 의 동사를 쓴다 — 「고치다 · 지우다 · 넣다 · 누르다 ·
   돌다」 같은 구어는 쓰지 않는다.
3. **부정은 「~하지 않습니다」.** 「안 보냅니다」 가 아니라 「보내지 않습니다」.
4. **개념어는 하나로.** 같은 것을 두 이름으로 부르지 않는다(아래 「개념」).

새 기능을 만들 때는 **화면을 짜기 전에** 그 기능의 말을 이 표에 먼저 적는다(AGENTS.md 「화면 용어」).

## 개념 — 중계

| 쓰는 말 | 뜻 | 다른 말로 부르지 않는다 |
| --- | --- | --- |
| 원천 시스템 · 원천 | 데이터를 내주는 레거시 시스템(PLM · MES)과, 중계가 받는 그 API · 파일 · 공유 폴더. **원천 시스템의 DB 에 바로 붙지 않는다** | 소스 · 출처 · 레거시(화면에서) |
| 대상 · 대상 인스턴스 | 중계가 적재하는 등록된 SP 인스턴스(자주검증 Datahub · 제조 데이터허브). 다른 플랫폼에는 대상이 뿌린다 | 타깃 · 목적지 · 허브(그 인스턴스의 이름이 아니면) |
| 파이프라인 | 원천 하나 → 레시피 → 대상 하나의 묶음. slug 로 부른다 | 연동 · 잡 · 플로우 · 인터페이스 |
| 정의 · 정의 판 · 정의 파일 | 파이프라인의 설정(`relay-pipeline/1` — 원천 어댑터 · 대상 · 일정 · 자동 적용). 판은 DB 에 차례로 남는 것, 파일은 서버의 정의 폴더에 둔 것. 같은 slug 면 사용 중인 판이 파일을 이긴다 | 설정 · 구성 · 버전(「판」 으로) |
| 레시피 · 레시피 판 | 원천의 칸을 대상 타입의 칸으로 바꾸는 규칙(`sp-table/1`) | 매핑 · 변환 규칙 · 룰 |
| 초안 · 초안(미사용) | 작성했지만 아직 사용하지 않는 판. 사용 중인 판이 없는 새 파이프라인은 지도에 「초안(미사용)」 으로 표시되고 실행되지 않는다 | 임시 · 드래프트 · 초안(꺼짐) |
| 사용 · 사용 중 · 사용 시작 · 사용 종료 | 판을 실행에 쓰기 시작하는 것(단추 「사용」)과 그 상태 · 시각, 그리고 다른 판을 사용해 물러난 판의 상태(언제든 다시 사용할 수 있다). **사람만 화면에서** 한다 — 토큰(MCP)의 사용 요청은 거절한다. 현재 쓰는 판을 가리킬 때는 「현재 정의 · 현재 레시피」 | 켜기 · 켜짐 · 켠 시각 · 내려 둠 · 활성화 · 활성 · ON |
| 폐기 | 초안을 더 쓰지 않게 하는 것(초안만). 목록에 「폐기」 로 남고 본문은 볼 수 있다. AI 도 자기 시험 초안을 폐기할 수 있다 | 버리기 · 버림 · 삭제(판의) |
| 작성 경로 | 판을 작성한 곳 — 화면 · MCP | 지은 곳 · 출처 |
| 탐색 · 원천 탐색 | 주소 · 인증만으로 원천을 불러 칸의 자리 · 보기 값 · 열 이름을 보는 것 | 스캔 · 디스커버리 |
| 시험 · 정의 시험 · 레시피 시험 | 대상에 아무것도 보내지 않고 원천을 받아 보고 · 레시피로 바꿔 보고 · 기준 출력과 견주는 것. 결과의 「사용하면 보낼 것」 이 사용한 뒤 첫 실행이 보낼 건수다 | 테스트 실행 · 드라이런 · 미리 실행 |
| 미러 · 추가 · 변경 · 그대로 · 삭제 | 원천 키마다 최신 행을 보관한 것 — 증분으로 받은 것을 여기에 모아 레시피가 늘 전체를 바꾼다. 실행 요약의 「추가 · 변경 · 그대로 · 삭제」 는 미러 행의 건수다(대상 객체의 「생성 · 변경 · 삭제」 와 다르다) | 캐시 · 스냅샷 · 사본 · 새 · 바뀜 · 빠짐(미러의) |
| 실행 · 지금 실행 | 받기 · 변환 · 비교 · 미리 보기까지. **대상은 아직 바뀌지 않는다** — 계획만 생성한다 | 동기화 · 싱크 · 돌리기 · 배치 |
| 일정 | 파이프라인을 언제 실행하나(정의의 `schedule`) — 「수동」 · 「매일 01:00」 · 「60분마다」 | 스케줄 · 크론 |
| 계획 · 계획 생성 | 실행이 대상 SP 의 검토함에 **미리 보기**로 등록한 바뀐 것의 묶음. 파이프라인마다 하나만 기다린다 | 플랜 · 변경안 · 계획 올림 |
| 미리 보기 | 대상 SP 가 계획을 받아 무엇이 바뀌나 세어 둔 것(적용 전). 띄어 쓴다 — 틀의 「미리보기」(붙여 씀)는 사진의 작은 그림이다 | 프리뷰 · 미리보기(계획의) · 드라이런 |
| 생성 · 변경 · 삭제(계획의 건수) | 계획이 대상에 만드는 것 · 수정하는 것 · 사용 중지 · 해제하는 것. **삭제는 객체를 지우지 않고 사용 중지하고, 관계는 해제한다** | 새 · 바뀜 · 무덤 · 지움 · 선 끊기 |
| 삭제 표시 | 원천이 그 행이 삭제됐다고 알리는 칸 | 지움 표시 · 삭제 플래그 |
| 미해결 | 레시피가 풀지 못한 줄(참조할 상대를 못 찾음 등). 남으면 그 실행은 멈춘다 | 미매핑 · 실패 줄 · 오류 줄 |
| 적용 · 적용 대기 | 계획을 대상에 반영하는 것(단추 「적용」)과 반영을 기다리는 상태 | 반영 · 커밋 · 배포 · 승인 |
| 자동 적용 | 타이머의 실행이 만든 계획이 기준(사람 적용 3번 뒤 · 오류 0 · 삭제 없을 때만(또는 삭제 포함) · 건수 상한)을 넘으면 사람 없이 적용하는 것. 판마다 정의에 적고, 사람이 정한다. 적지 않았으면 「미사용」 | 오토 커밋 · 자동 반영 · 자동 승인 · 끔 |
| 기준 출력 · 기준 | 지난번 **적용된** 출력 — 다음 실행의 비교와 대조가 이것과 견준다 | 베이스라인 · 스냅샷 · 마지막 결과 |
| 정상 · 적용 대기 · 멈춤 · 실패 · 정의 오류 · 실행 전 | 파이프라인의 상태. 멈춤은 미해결 · 계획 오류로 보내지 않은 것, 실패는 작업이 오류로 끝난 것(원천이 닿지 않음 등), 정의 오류는 정의를 읽지 못한 것 | 에러 · 중단 · 블록 · 비정상 · 아직 안 돌았음 |
| 대조 | 대상 SP 의 실제 객체를 기준 출력과 견주는 것 — **읽기만 한다**. 며칠마다 타이머가, 또는 사람이 화면에서 | 리컨실 · 동기화 점검 · 검증 · 정합성 체크 |
| 어긋남 — 빠짐 · 안 씀 · 다름 · 대상에만 | 대조가 찾은 것의 네 가지: 기준에는 있는데 대상에 없음 · 대상에서 사용 중지됨 · 칸 값이 다름 · 대상에만 있음 | 불일치 · 드리프트 · 누락 · 초과 |
| 확인 못 한 참조 | 참조 칸의 상대를 대상에서 찾지 못해 견주지 못한 것 — 어긋남으로 세지 않고 따로 적는다 | 미확인 · 참조 오류 |
| 보정 계획 · 보정 계획 생성 | 어긋난 줄만 기준대로 다시 보내는 계획(미리 보기). 적용은 사람이 하고, 적용하면 같은 작업이 다시 대조한다 | 맞추기 계획 · 복구 계획 · 리싱크 · 보정 계획 올리기 |
| 연결 지도 | 첫 화면 — 원천 시스템 → 원천 → 파이프라인 → 대상 → 타입의 흐름도 | 대시보드 · 토폴로지 · 맵 |
| 실행 실패 · 실행 멈춤 · 실행 복구 · 대상과 어긋남 N건 · 대조 실패 · 대상과 일치 · 적용 대기 | 시스템 관리자에게 가는 알림의 제목 — **바뀔 때만** 한 번 간다 | 경보 · 장애 알림 · 에러 알림 |

## 개념 — 틀에서 온 것(중계 화면에 나오는 것만)

| 쓰는 말 | 뜻 | 다른 말로 부르지 않는다 |
| --- | --- | --- |
| 타입 · 객체 · 관계 | 대상 SP 의 객체의 종류 · 그 인스턴스 · 객체 사이의 연결 | 종류 · 클래스 · 레코드 · 링크 |
| 식별자 · 이름 | 타입 안에서 유일한 코드(`key`) · 사람이 읽는 표시명(`label`) | 키 · 코드 · 라벨 |
| 안 씀 | 객체의 상태 — 사용 중지된 것(`deprecated`) | 삭제됨 · 비활성 |
| 작업 | 오래 걸리는 일 — 워커가 실행하고 「작업」 화면에 남는다 | 잡 · 태스크 · 배치 |
| 남은 일 | 시스템 관리자의 홈에 표시되는 처리할 것의 목록 | 할 일 · 대기열 · 경고 |
| 새로 고침 · 거르기 · 거르기 해제 | 화면의 내용을 다시 불러오는 단추 · 목록을 조건으로 좁히는 것과 그 해제 | 다시 읽기 · 필터 · 거르기 풀기 |

## 어디까지 적용됐나

- 2026-11-05 — 이 표를 지었다. 중계 화면(`frontend/src/modules/relay` · 상태 배지) · 중계 서버의 메시지 · MCP 안내를
  이 표로 맞췄다(「켜기 · 켜진 판」 → 「사용 · 사용 중인 판」, 「버리기」 → 「폐기」, 「보정 계획 올리기」 → 「보정 계획
  생성」, 「지은 곳」 → 「작성 경로」, 「무덤 · 지움」 → 「삭제」, 「초안(꺼짐)」 → 「초안(미사용)」, 「내려 둠」 →
  「사용 종료」, 「아직 안 돌았음」 → 「실행 전」, 「다시 읽기」 → 「새로 고침」, 구어 동사).
- 그대로 둔 것: 틀의 「~보기 · 접기 · 펼치기 · 불러오기」 단추(틀도 쓴다), 체크 상자 「덮기」(사람이 수정한 칸도 원천
  값으로 덮어쓰는 선택 — 더 나은 명사가 없다), 작업 진행 단계의 이름(「정의 읽기」 · 「받기 · 변환 · 비교 · 미리 보기」).
- 틀에서 온 화면(계정 · 작업 · 서버 · 알림 …)은 틀의 문구 그대로다 — 고칠 때 이 표를 따른다.
- 문서(`docs/` · `deploy/*.md`)는 화면 문구가 아니지만, **화면의 단추 · 상태를 가리킬 때는 화면과 같은 말**을 쓴다.
